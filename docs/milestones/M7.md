# M7 — GPUI inputs, forms, focus, keyboard, accessibility and scripted interaction

Branch: `milestone/m7`, rebased onto `main` at `8d82617` (the M7 work started at `074cdae`). This report covers SPEC §14.1 M7
and DESIGN §§6.7, 7 and 9. Data components, panic containment and the real-model
loop remain M8.

## Built

- **Core contract fixes.**
  - `UiEvent::{Activate,Edit,Blur}` now carries the patch wire's `NodePath`
    instead of an IR `NodeId` hash the renderer cannot compute. `Session::event`
    resolves the path and ignores unknown/removed ones. `Session::activate`
    keeps the IR-id entry point for hosts that already hold one.
  - A submit-only `Button` (no `on_click`) can activate its form: the renderer
    sends the form's `on_submit` handle with the button's path, and the core
    accepts it only for a `submit: true` button in exactly that form. A button
    with both props still runs its own plan and then the form plan.
  - `Session::state_values()` exposes `{value, rev, origin}` per bound slot.
- **`UiView` input state.** Inputs and controls live on the retained
  `NodeView` entities. `Input`/`TextArea` use `InputState`/`TextareaState`;
  `Select` uses `SelectState<SearchableVec<String>>`; select, switch, radio and
  checkbox groups own stable focus handles. `set_props`, `append_text` and
  status changes notify the input entity without recreating its widget, so typed
  text, cursor, selection and focus survive rebuilds.
- **Store-to-widget rule.** `sync_state` ignores the view's own `User` echoes,
  keeps the focused widget authoritative, defers a non-user write until blur,
  and applies initial bound values on load. A restored `User` value is not an
  echo and fills the widget (scripted test included). The form demo and gallery
  both call it after applying session patches.
- **Form.** DESIGN §6 rule 7 anatomy directly: 12 px field gap, 6 px label gap,
  4 px error gap, 16 px submit gap; labels `small` weight 500; errors `caption`
  `danger.fg`; submit buttons natural width. Errors are shown only when
  `touched` and an `error` prop is present. The core decides validity.
- **Inputs.** `Input`, `TextArea`, `Select`, `Checkbox`, `CheckboxGroup`,
  `RadioGroup`, `Switch` and `Button` are implemented:
  - Text inputs: 32 px shell, 1 px input border, `md` radius, body text,
    placeholder, email/url content types; TextArea `rows × 20 + 12`.
  - Select: kit overlay/menu and keyboard selection, DESIGN shell and a
    theme-token chevron; the kit caret is made transparent because icon assets
    are not guaranteed in headless captures.
  - Checkbox/radio/switch use `gpui-base` primitives with DESIGN geometry:
    16 px accent checkbox, 16 px radio dot, 32×18 switch. The component
    checkbox/switch were rejected because their primary/36×20 anatomy differs.
  - Button: kit button with DESIGN tone, 32 px height, 12 px padding and base
    keyboard/a11y behavior.
- **Focus and keyboard.** `focus_root` starts a `tab_group`; the view unbinds the
  kit Root's Tab/TabPrev and the input-local indent bindings, then handles
  Tab/Shift-Tab itself and emits `Blur` for the field it leaves. Pointer clicks
  focus the field and blur the previous one. Escape clears focus. Enter submits
  from a single-line field only when the form has one submit button; Enter
  activates a focused button; arrow keys drive Select and RadioGroup. Frozen
  views render disabled and emit nothing.
- **Accessibility.** Every control has an accesskit role, accessible label and
  value/toggle (SPEC §10.10). The pinned test platform has no OS adapter, so
  M7 measures `Element::write_a11y_info` on the same primitive and records the
  fact in PINS.md. OS coverage remains unverified/full-coverage phase 2.
- **Host extensions.** SPEC §10.14 adds `with_extension`/`register_extension`
  for a host-defined `Library` component. Extensions are leaf builders; the IR
  and patch protocol are unchanged.
- **Demo and gallery.** `examples/25-form-controls.ui` exercises every M7 input
  in one form. `form-demo` is the runnable host: it prints each `ui-event`,
  request and model event, applies patches, syncs state, and supports
  `--screenshot`, `--headless`, `--self-test` and `--mode`. The gallery state
  sheet now shows live inputs, an error field, checked/selected controls and
  disabled input/switch states instead of M7 placeholders.
- **Scripted tests.** `crates/genui-gpui/tests/interaction.rs` has 12 headless
  tests: every control's Edit, validation gating, submit-only button, Enter in a
  field, Tab/Shift-Tab, blur, Escape, patch rebuild survival, streaming status,
  frozen view, host extension and the accesskit projection. The keyboard-only
  test loads the form-demo example and reaches submit without a pointer.

## Screenshot review against DESIGN.md

Reviewed the 52-image gallery, the state sheet and the form demo in both modes.
Fixed findings:

- **Select had no visible chevron** in headless captures. The kit caret is an
  icon asset; M7 draws a token-sized chevron and hides the kit caret.
- **Dark-mode input text was invisible.** `appearance(false)` left the text color
  at the platform default; Input, TextArea and Select now set
  `foreground` explicitly.
- **Checkbox checked fill was black** (component uses theme `primary`); replaced
  with the DESIGN `accent` box and a check mark.
- **Switch was 36×20** (component); replaced with the 32×18 DESIGN track.
- **Buttons and badges stretched in columns/forms.** A leaf `NodeView` wrapper
  forced `w_full`; focusable leaves now return their natural-width element and
  toolbars/forms left-align them.
- **RadioGroup used a 12 px gap** (component); the renderer draws the DESIGN 8 px
  gap and row wrapping rule with base radio primitives.
- **Disabled fields were double-faded** from shell + wrapper; the wrapper no
  longer applies a second opacity.
- **State sheet did not test disabled inputs/switches**; added them, plus the
  error field and initial checked/selected states.

Logged findings (not fixed in M7, with reasons):

- **Static screenshots cannot force keyboard focus.** Focus rings are verified by
  the scripted tests and by the pinned `focus_ring_style` path, not by a gallery
  override.
- **Motion is unchanged.** Streaming fades and reduced motion remain DESIGN §8
  M8 work (ROADMAP item 1).
- **NumberInput/Slider/DateInput are not phase-1 std components.** `Input` with
  `kind: "number"|"integer"` is the number field. Slider and DateInput are absent
  from SPEC §8.8; adding them changes the M2 Library Spec hash, so this is an
  owner-scope decision, not an M7 renderer addition (DECISIONS.md).
- **OS accessibility coverage is unverified.** The test platform has no adapter;
  the pinned accesskit projection is measured. Full coverage is phase 2.
- **Extensions are leaf-only.** Child traversal and panic containment stay M8.
- **Select menu item targeting by ID is not exposed**; the scripted test drives
  the menu with Enter/down/Enter, which exercises the same selection path.
